## Mini App 统一工作入口

设计 SSOT 为 [MCP Apps](../mcp-apps/SPEC.md)。目标是让人和 Agent 通过同一领域操作完成工作，复用当前 runtime、host 与业务 owner。以下是有界实施顺序；可独立的 owner 切片并行开发，共享合同先落地，主线吸收按依赖顺序进行。完成一项就删除该行，当前行为回填相应主题 owner。

| 顺序与负责人 | 当前断点及写入范围 | 实施与依赖 | 可观察完成条件 |
| --- | --- | --- | --- |
| 1 · Framework / App | `src/mcp-app/view.js` 主要按 JSON 形状展示；App 需统一产品表达 | 建立进度、产物、审阅视图组件；复用现有列表详情、上下文和官方 MCP Apps SDK；App 产品合同引用本规范 | 不同 owner 数据通过同一组件呈现；可直接找到可用产物与下一步，保留原始数据查看 |
| 2 · Relay | `workbench/style.css` 固定浅色；执行反馈与共享工作台重复 | 消费 host theme/viewport，收敛通用加载、错误、编辑保护与结果反馈；邮件编辑、草稿与发送仍归 Relay | 阅读、修改、保存路径可用；主题跟随宿主；失败保留输入，结果来自 owner |
| 3 · OBF / 标准智能体 | OBF adapter 要求状态、清单路径；通用产物入口缺少项目上下文 | OBF 先以当前 workspace/task 解析产物，再复用到 MAG/RCA/OCC/MAS 的适用视图；不新增跨领域数据副本 | 当前任务直接打开领域进度与产物；歧义明确选择，不猜文件；领域 verdict 保留原义 |
| 4 · Framework / Studio | 内置 runtime MCP 视图只读，现有 App runtime action 尚未接入 | 将现有当前可用动作投影和执行入口接入工作台；长任务使用 Task/StageRun；依赖第 1 项 | 界面能发起或继续当前允许的工作并回读同一任务；重新打开不重复派发 |

| 6 · 各文档 owner | 白皮书尚未描述最终统一工作入口 | 实现完成后更新 Framework、OPL、App 及实际受影响领域白皮书源，并用既有生成器处理投影 | 正文只陈述已实现能力；链接、生成物与源一致，不把源码验证写成安装或业务验收 |

统一凭证任务持有 Connect 的连接、消费者授权、调用与品牌整合；本任务持有 Mini App 展示、上下文和工作入口。共享的 App 产品合同、架构文档与白皮书按具体段落语义合并，Mini App 不新增凭据存储或授权 broker。验证按改动风险选择现有检查并运行实际交互路径，不添加通用资格门禁。
