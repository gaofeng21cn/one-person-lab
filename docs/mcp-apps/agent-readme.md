# OPL 智能体 README 写作指南

根 README 面向第一次了解产品、正在判断是否值得一试的人。读者应该能看懂自己可以交办什么、智能体会怎样推进、自己何时需要介入，以及怎样开始。家族品牌和语言入口沿用 [Agent 原生应用开发标准](../policies/agent-native-app-policy.md#品牌与公开入口)。

## 写作原则

1. **从一件真实工作说起。** 在开头说清服务对象、常遇到的场景和希望交付的结果。选一个能贯穿全文的工作对象，如一次就诊、一项课题、一本书。
2. **用工作方式讲设计。** 写清智能体如何利用已有材料和工作环境，主动推进哪些步骤，在哪里把决定交给人，以及如何带着人的决定继续。只写对读者有影响的原则，用领域里的具体事说明。
3. **说清什么叫做完。** 让读者知道会看到什么产物或系统结果、怎样核对、还有什么需要处理。如果任务会跨天或需要多轮修订，交代下一次怎样从原来的材料、版本和进度接着做。
4. **示例用用户自己的话。** 写出任务目标、已有资料和希望收到的结果。自然语言入口用读者平常的说法。产品若主要面向开发者，可以给一个真实可用的命令。示意图用来解释工作如何推进，有合适的图就放在定位之后。
5. **给出一个现在可以走通的起点。** 用简短的安装入口和第一件可做的事收尾。开发中的工作放在相关场景或简短的进展段落里。完整教程、技术架构、配置、发布机制和验收清单由各自文档维护。
6. **双语各自自然，信息一致。** 保留现有语言路径、产品名和品牌图。回读两版，核对交付物、授权与确认点、已开放和计划中的能力、安装入口以及图片和链接。
